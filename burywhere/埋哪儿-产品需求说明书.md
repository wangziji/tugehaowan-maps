> 一句话说明：**「埋哪儿」是给刚失去亲人、要在 3~7 天内完成选墓到下葬决策的家属用的——在一张地图上把「选墓园、看风水、看实景、排路线、办仪式、后续祭扫」一次办完，不用再跑断腿。**

## 一、背景与问题

### 1.1 场景事实

亲人离世后，家属通常在 **3~7 天**内要完成一条高度压缩的决策链：

```
选墓园 → 看墓位 → 谈价格 → 定穴位 → 安排下葬车队与路线 → 办告别仪式 → 后续清明/忌日祭扫
```

这条链上，**80% 的决策依赖"地理位置"**，但今天没有任何一个产品把地理信息做成主线。

### 1.2 用户痛点（按严重程度）

| # | 痛点 | 现状 | 后果 |
|---|---|---|---|
| P1 | **信息不透明** | 墓园价格、空位、朝向靠中介口头报价，无公开比价 | 同规格墓位价差可达 2~3 倍 |
| P2 | **来回跑断腿** | 一个城市 10+ 墓园，实地看完要 3~5 天、跑几百公里 | 决策窗口被体力消耗吃掉 |
| P3 | **风水诉求无工具** | 家属普遍在意朝向/形势，但只能靠"懂行的亲戚"或中介话术 | 决策焦虑 + 被迷信营销裹挟 |
| P4 | **下葬日路线失控** | 车队、亲友从殡仪馆/家里出发，无统一路线与时刻表 | 迟到、走散、错过吉时 |
| P5 | **异地亲属缺席** | 在外地/国外无法到场，也无法参与祭扫 | 情感欠账 |
| P6 | **烧纸污染与火险** | 传统烧纸引发山火、PM2.5 峰值、园区禁烧 | 政策收紧，但情感需求仍在 |
| P7 | **后续祭扫断联** | 一年后找不到穴位的园区入口/区排号 | 清明排队两小时 |

### 1.3 为什么必须"含地图图面"

去掉地图，这个产品**不成立**：

- 墓园的**距离**是家属第一筛选条件（"别太远，以后要常去"）；
- **朝向、形势、明堂**本质上都是空间关系；
- **下葬路线**是两条坐标之间的路径与时刻问题；
- **3D 看墓**需要园区地理级坐标定位到穴位；
- **云祭扫**需要"这个人在这一处"的地理锚点。

## 二、目标用户与使用场景

### 2.1 角色定义

| 角色 | 描述 | 核心诉求 | 关键行为 |
|---|---|---|---|
| **主决策人**（核心用户） | 35~55 岁，逝者子女/配偶，首次办丧事 | 7 天内定下来，不花冤枉钱，不留遗憾 | 比价、对比、看实景、问风水 |
| **异地亲属** | 在外地/国外，无法到场 | 参与告别、持续祭扫 | 云祭扫、直播、代客祭扫 |
| **家中长辈** | 60+，在意传统礼俗 | 朝向、吉日、仪式合规 | 看风水报告、选吉时 |
| **墓园方 / 殡葬服务商** | B 端供给 | 获客、透明化展示、减少无效带看 | 上架园区、穴位、实景数据 |
| **殡葬顾问** | 平台或机构服务者 | 承接咨询转化 | 在线咨询、报价单、订单 |

### 2.2 典型场景故事

> **场景 A｜三天定墓**
> 李女士的父亲周四去世，周日要下葬。她打开「埋哪儿」，定位在深圳市殡仪馆，输入预算 8 万内、距离 30km 内、要立碑、希望坐北朝南。地图立刻从 12 个园区筛出 4 个；她点开 3D 实景挨个看穴位朝向，用 AI 堪舆对最中意的两处跑了报告，当场预约周六看墓 + 路线规划，把路线链接发到家族群，车队按建议时刻出发。

> **场景 B｜清明不排队**
> 小王在杭州工作，父亲的墓在深圳。清明前他在「埋哪儿」约了代客祭扫，当天收到 6 张现场照片 + 3 分钟直播回放；他自己用 AR 环保烧纸远程撒了一次纸钱，攒了 120 环保积分换了一棵实体心愿树。

## 三、产品定位与差异化

| 维度 | 传统墓园官网 | 殡葬中介 | 地图 App | **埋哪儿** |
|---|---|---|---|---|
| 多园比价 | ✗ | 部分（不透明） | ✗ | ✅ 地图上同屏比价 |
| 地理筛选 | ✗ | ✗ | ✅ 但无墓园数据 | ✅ 距离/朝向/行政区 |
| AI 风水 | ✗ | 人工话术 | ✗ | ✅ 结构化报告 + 免责 |
| 3D 看墓 | 少数 | ✗ | ✗ | ✅ 穴位级 |
| 下葬路线 | ✗ | 口头约定 | ✅ 通用 | ✅ 殡葬场景化（吉时倒推 + 沿途服务点） |
| AR / 云祭扫 | ✗ | ✗ | ✗ | ✅ 环保替代 + 远程参与 |

**差异化一句话**：把「殡葬决策」做成一张可筛选、可对比、可导航、可远程参与的**地图**。

### 4.1 地图图层设计表（对应赛题"五种常见图层"）

| 图层 | 数据形态 | 在「埋哪儿」的语义 | 交互 |
|---|---|---|---|
| **打点 POI** | 一批坐标点（名称+经纬度+属性） | 墓园 / 骨灰堂 / 海葬点 / 生态葬园 | 点击出详情卡，筛选后实时增删 |
| **热力** | 多坐标 + 权重 | 墓位单价热度分布（元/㎡） | 滑块调权重口径（单价/空位/关注度） |
| **行政区着色** | 每个区一个数值 → 填色 | 各区**空位紧张度**（绿=充足→红=紧张） | 点击区多边形 → 该区园区列表 |
| **轨迹 / 连线** | 一串有序坐标 → 折线 | 下葬路线（殡仪馆→墓园）；家→墓园连线 | 切换 4 种策略，Hover 看耗时 |
| **弧线连线** | 两点弧线 | "从哪里来"关系图：异地亲属城市 → 墓园 | 展示参与人来源分布 |

## 六、详细页面设计

> 统一设计规范见 §6.0；每个页面按「布局分区 → 元素清单 → 交互 → 状态与异常」描述。

### 6.0 全局设计规范

**配色（素雅克制，避免娱乐化）**

| 用途 | 色值 | 说明 |
|---|---|---|
| 主色 竹青 | `#4A7C6F` | 生命、肃穆 |
| 辅色 烛黄 | `#C9A227` | 烛光、纪念 |
| 底色 素白 | `#F7F6F3` | 纸帛质感 |
| 文字 青灰 | `#2C3A38` | 正文 |
| 次文字 | `#7A8A86` | 辅助 |
| 警示 | `#B4453C` | 空位紧张 / 价格超预算 |

**墓园类型色板（POI 着色）**

| 类型 | 颜色 | 图标 |
|---|---|---|
| 传统立碑墓园 | `#4A7C6F` | 碑形 |
| 生态葬（树葬/花坛葬/草坪葬） | `#7BA05B` | 叶形 |
| 骨灰堂 / 壁葬 | `#6E7B8B` | 塔形 |
| 海葬 / 水葬点 | `#3E7CA8` | 浪形 |
| 经营性 / 公益性 | 边框实线 / 虚线区分 | — |

**组件约定**
- 卡片圆角 14px，阴影 `0 2px 12px rgba(44,58,56,.08)`；
- 底部抽屉支持三段高度（收起 96px / 半屏 50% / 全屏 92%），拖拽把手；
- 所有价格统一展示"起价 + 区间"，禁用"面议"；
- 地图容器固定高度（移动端 `calc(100vh - 64px)`），禁止 flex 自适应导致底图不渲染。

### P1 首页 · 选址地图

**布局分区**

```
┌─────────────────────────────────────────┐
│ ① 顶栏：Logo 埋哪儿 | 城市切换 | 搜索框 | 我的 │
├─────────────────────────────────────────┤
│ ② 图层工具条（地图右上，竖直胶囊）        │
│    [打点][热力][行政区][连线]  [定位]     │
│                                          │
│ ③ 地图主体（墓园 POI + 当前图层）         │
│                                          │
│ ④ 筛选栏（地图上方横向 chip）             │
│    预算 距离 葬式 朝向 宗教 资质          │
├─────────────────────────────────────────┤
│ ⑤ 底部抽屉：结果列表（默认收起为计数条）   │
│    共 12 处 · 已筛出 4 处   [列表/对比]   │
└─────────────────────────────────────────┘
```

**元素清单**

| 区 | 元素 | 说明 |
|---|---|---|
| ① | 城市切换 | 默认按定位城市，支持手动切换 |
| ① | 搜索框 | 支持墓园名 / 地名 / "南山 陵园" 自然语言 |
| ② | 图层工具条 | 4 个图层单选切换 + 1 个回定位按钮 |
| ② | 比例尺/路况 | 右下角 |
| ③ | POI 打点 | 按类型着色，选中态放大 1.3× 并常驻气泡 |
| ③ | 家的锚点 | 蓝色三角，可长按拖动 |
| ④ | 筛选 chip | 展开为底部弹层，多选 + 滑块 |
| ⑤ | 结果计数条 | 显示"已筛出 N / 共 M"，点击展开列表 |

**交互流程**

1. 进入页面 → 请求定位 → 成功则地图居中到用户位置，失败降级到城市中心并提示"已定位到深圳市中心，可手动拖动家的锚点"；
2. 默认「打点」图层，加载城市内全部在架墓园，按类型着色；
3. 用户修改任一筛选条件 → **防抖 300ms** → 地图 marker 增量更新（保留未变项，避免闪烁）+ 计数条数字滚动 + 抽屉列表同步；
4. 点击 marker → 地图飞行到该点（`easeTo`，zoom→15）→ 弹出气泡（名称/起价/距离）→ 底部抽屉自动升到半屏展示 **P2**；
5. 切换「热力」→ 以墓位单价为权重渲染热力，底部出现权重口径切换（单价/空位/关注度）；
6. 切换「行政区」→ 各区按空位紧张度填色 + 图例（充足→紧张），点击区多边形 → 抽屉列出该区园区；
7. 切换「连线」→ 从"家的锚点"到各筛出园区画直线，线宽随距离，Hover 显示"车程 xx 分钟"；
8. 勾选"对比"（≤3，超出 toast 提示"最多对比 3 处"）→ 底部出现对比条 → 点「开始对比」打开对比表（价格/距离/朝向/空位/生态葬/评分/资质）；
9. 收藏 → 星标填充 + toast"已加入我的收藏"。

**状态与异常**

| 状态 | 表现 |
|---|---|
| 加载中 | 地图骨架 + marker 位置脉冲占位 |
| 定位失败/拒绝 | 降级城市中心，顶部黄条"未获取到定位，已按深圳市中心展示" + 一键重试 |
| 筛出 0 结果 | 地图置灰底图 + 空态插画 + "放宽预算 / 扩大距离"两个快捷操作 |
| 数据加载失败 | 地图保留，抽屉内错误态 + 重试按钮 |
| 园区已下架 | marker 灰化 + 点击提示"该园区已暂停展示" |

```
① 拖拽把手
② 头图（园区实景，可左右滑）
③ 标题行：园区名 [经营性/公益性标签]  ⭐收藏
④ 关键指标行：4.6分 | 距您 12.4km | 起价 ¥38,000 | 空位 充足
⑤ 标签行：立碑 · 树葬 · 壁葬 · 坐北朝南 · 可海葬 · 资质齐全
⑥ 卡片：AI 堪舆速览（形势 88 / 朝向 92，点击进入 P5）
⑦ 卡片：3D 实景（缩略图 + "进入漫游"）
⑧ 卡片：下葬路线（"从这里规划" → P7）
⑨ 穴位列表（前 3 条 + 查看全部）
⑩ 底部操作条：[在线咨询] [预约看墓]
```

**交互**
- 抽屉拖拽三段；拖到全屏时顶部变为园区名标题栏；
- 点击 ⑥ → 跳 P4 并预填园区；点击 ⑦ → 跳 P6；点击 ⑧ → 跳 P7 并以该园区为终点；
- 「预约看墓」→ 选择日期时间 + 人数 + 是否需要接送 → 提交后生成服务单，进入 P11；
- 「在线咨询」→ 打开顾问对话（人工/AI 混合），自动带上园区上下文。

**异常**：穴位售罄 → 列表显示"该葬式暂无空位"并推荐同类；非营业时间 → 预约按钮置灰 + "明日 09:00 后可预约"。

### P4 AI 风水堪舆（输入页）

**布局**

```
① 标题：AI 风水堪舆（副标题：传统形势学参考，不构成任何承诺）
② 表单
   - 逝者生辰：日期选择器 + 时辰下拉（子丑寅卯…）
   - 逝者性别
   - 候选园区：下拉（可多选，≤2）
   - 穴位坐向：廿四山下拉（子/癸/丑/艮/寅/甲/卯/乙/辰/巽/巳/丙/午/丁/未/坤/申/庚/酉/辛/戌/乾/亥/壬）
   - 周边环境：照片上传（≤3 张，可跳过）
   - 家属偏好：多选（明堂开阔/背有靠山/近水/安静/远离主干道）
③ 按钮：[开始堪舆]
④ 说明折叠：我们怎么算？（数据来源与免责）
```

**交互**
- 表单校验：生辰必填，园区或坐向至少填一项；
- 点击「开始堪舆」→ 全屏 loading（3 段式文案轮播：“正在读取地形水文…”“正在比对廿四山坐向…”“正在生成堪舆报告…”，约 2.5s）→ 跳 P5；
- 历史记录入口：右上角「我的报告」。

**异常**：网络失败 → 保留表单内容 + 重试；照片超 10MB → 压缩提示；输入生辰超出合理范围 → 内联报错。

### P7 下葬路线规划

**布局**

```
① 起终点输入卡
   起点：[深圳市殡仪馆 ▾]（可切换：当前位置/家里/自定义）
   途经（可选）：花圈店 / 接亲属点
   终点：[已选墓园 ▾]
   下葬吉时：[2026-10-19 10:30 ▾]
② 方案区（3 张卡，横滑）
   [最快 42分钟 31km 红灯8] [最短 38分钟 28km 红灯12] [避堵 46分钟 33km]
③ 地图：当前方案轨迹高亮，其余方案灰线
④ 沿途服务点开关：花圈/停车/休息/洗手间/加油站（POI 打点，可点看详情）
⑤ 底部：[生成车队方案] [分享到家族群]
```

**交互**
1. 终点为空时提示"请先在地图选择墓园" + 一键跳 P1；
2. 输入变化 → 调用驾车路径服务，返回 3 个策略（最快/最短/避高速/实时路况）；
3. 点击方案卡 → 地图重绘该轨迹并自适应视野（`fitBounds`）；
4. 打开服务点开关 → 沿轨迹buffer 检索并在图上打点；
5. 「生成车队方案」→ 按吉时倒推：以方案耗时 ×1.3（冗余系数）+ 仪式预留 30min → 输出 **P8 时刻表**；
6. 「分享到家族群」→ 生成分享链接 + 6 位口令，链接页为只读路线卡片（含集合点、出发时刻、联系人）。

**异常**：路径服务失败 → 保留起终点，提示"路线服务暂不可用，可先查看直线距离"；起终点同城外 → 提示"跨城下葬请咨询顾问安排专车"。

## 九、技术方案

### 9.1 地图与位置服务（合规）

| 项 | 方案 |
|---|---|
| 底图 | **腾讯地图 JSAPI GL**，`https://map.qq.com/api/gljs?v=1.exp&libraries=service,visualization` |
| 坐标系 | **GCJ-02**（火星坐标），全部数据入库前统一转换 |
| 密钥 | 前端**不落任何 key**：通过 `window._TMapSecurityConfig.serviceHost` 走本地代理（默认场景）；生产环境需自行申请 key 并配置 Referer 白名单 + 后端代理签名 |
| POI 打点 | `TMap.MultiMarker` + 自定义 `MarkerStyle`（内联 SVG，不引用官方 demo 图片） |
| 热力 | `TMap.visualization.HeatMap`（需 `libraries=visualization`） |
| 行政区着色 | `TMap.MultiPolygon` + 官方行政区划数据，按数值分级填色 |
| 路径规划 | `TMap.service.Driving({ policy: 'LEAST_TIME' \| 'LEAST_DISTANCE' \| 'AVOID_HIGHWAY' \| 'REAL_TRAFFIC' })`（**字符串**策略，不用常量） |
| 地点检索 | `TMap.service.Search` / `Suggestion`（沿途服务点、园区搜索） |
| 连接线 | `TMap.MultiPolyline`（轨迹）、弧线用多点插值 |
| 禁止项 | 不使用 Google/Bing/OSM/Mapbox；不传 `mapStyleId`；地图容器必须有固定高度 |

### 9.2 AI 风水堪舆

- **输入**：生辰（年月日时）、性别、园区/穴位、坐向（廿四山）、环境照片、偏好；
- **检索增强**：接入形势学公开术语库（靠山/明堂/水法/朝案/藏风聚气），做术语到白话的映射；
- **输出**：严格 JSON Schema → 前端渲染雷达与卡片

```json
{
  "total": 86,
  "dimensions": {"形势":88,"朝向":92,"水法":76,"明堂":85,"藏风":80},
  "readings": [{"dim":"朝向","score":92,"text":"坐北朝南，冬季采光充足…"}],
  "suggestions": {"good":["…"],"adjust":["…"],"avoid":["…"]},
  "recommend": {"orientation":"癸山丁向","zone":"B区 3-5排"},
  "disclaimer": "本报告基于传统形势学文化习俗生成，仅供情感与文化参考…"
}
```

- **风控**：系统提示词内置红线（不得预测吉凶祸福、不得承诺运势、不得涉及医疗/投资），输出后置合规过滤。

### 9.3 3D / AR

- 3D：Three.js 加载园区 glTF / 或 360° 全景序列（krpano 类）；日照用太阳位置算法（日期+经纬度+时辰）驱动方向光；
- AR：优先 WebXR `immersive-ar`；不支持时降级为"摄像头画面 + CSS 3D/Canvas 粒子"方案（功能等价，合规提示保留）。

### 9.4 前端

- 单页应用（原型为原生 HTML/CSS/JS 单文件，零构建，可直接打开）；生产建议 Vue3 + Vite；
- 状态：轻量 store（原型 `window.AppState`），生产 Pinia；
- 接口：`/api/parks`、`/api/graves`、`/api/fengshui`、`/api/route`、`/api/orders`、`/api/memorials`。

## 十一、合规与风险控制

1. **殡葬资质**：园区上架必须校验《经营性公墓许可证》/公益性等资质编号，无资质不得展示；
2. **价格透明**：禁止"面议"，必须展示分项报价与有效期；
3. **反迷信**：全站禁用"改运/旺财/荫庇后代"等因果承诺；AI 报告固定免责块；风水模块定位为"文化习俗参考"；
4. **环保**：AR 模块替代真实焚烧，园区禁烧提示常驻；公益树合作方需资质审核；
5. **地图合规**：仅使用合规底图（腾讯位置服务）；不标注军事禁区/涉密单位；国界与南海诸岛以国家标准底图为准，不自绘；
6. **个保法**：不收集、不公开他人位置数据；个人打卡/家庭坐标仅本地私有存储；纪念馆默认"仅家人可见"；
7. **未成年人**：纪念馆创建需实名，内容审核覆盖未成年人保护规则。
